## 4. 统计口径

- 类型：统计顶层 Java `class`、`interface`、`enum`、`record`；`record` 计为 class。
- LOC：统计有效代码行，并同时保留空行、注释行和文件数；注释及字符串内容不计为代码。
- 方法/WMC：统计普通方法，排除构造方法；WMC 每个普通方法权重为 1。
- RFC：本类普通方法集合与方法体中直接调用的外部方法名集合的并集大小。
- 圈复杂度：方法体初值为 1，按 `if`、`for`、`while`、`catch`、`case`、`&&`、`||` 和三元表达式等决策点累加。
- DIT：沿源码父类链计算，根类深度为 0；NOC 统计直接子类。
- CBO：统计直接引用的系统类型以及接口实现/扩展关系；JDK、Spring、第三方类型不计，继承边不计入 CBO。
- LCOM：按 `max(P-Q,0)` 计算。接口、无实例属性类型和纯 Repository 按与 S4 一致的兼容口径记为 0。
- 阈值：WMC>15、RFC>35、DIT>6、NOC>6、CBO>8、LCOM>1；圈复杂度阈值为 V(G)>10。

脚本是面向当前项目源码格式的轻量解析器，结果用于课程度量和证据留痕。复杂 Java 语法的工具解析边界已在 `S5/代码度量/tools/README.md` 中说明。

## 14. 超阈值对象与质量分析

机器可读超阈值明细见 `S5/代码度量/actual_over_threshold.csv`。当前共 24 条记录：23 条 CK 指标记录、1 条圈复杂度记录。

主要关注点：

1. `MaintenanceServiceImpl` 同时达到 WMC=17、RFC=64、CBO=13、LCOM=100，并包含唯一一个 V(G)>10 的方法 `listTasks`；它是当前最需要后续关注的实现类。
2. `DispatchServiceImpl`、`RepairOrderServiceImpl` 的 CBO 分别为 14，说明流程编排类直接协作对象较多。
3. 多个 ServiceImpl 的 LCOM 较高，反映方法对不同实体字段或流程阶段的访问分散；这是一项重构提示，不代表当前业务行为错误。
4. DIT 与 NOC 均未超过阈值，说明继承层次没有形成深层结构风险。
5. 测试通过率为 100%，但行覆盖率 69.60%、分支覆盖率 50.43%，未覆盖分支仍需在后续测试增强阶段补齐，尤其是异常、权限和边界分支。

## 15. S5 收口建议

- S5 正式报告中采用本目录 CSV 的实际值，不沿用 S4 的设计阶段数量作为实现值。
- 后续维护优先围绕 `MaintenanceServiceImpl` 的高 RFC、LCOM 和 `listTasks` 的复杂度进行小范围评估，保持图 4-3 业务职责边界不变。
- 后续测试增强优先覆盖 JaCoCo 未覆盖的异常、权限拒绝、状态分支和文件处理分支。
- 若课程要求使用其他商业工具复测，应保留本脚本结果，并在报告中明确工具、版本、过滤规则和口径差异，不覆盖原始证据。
